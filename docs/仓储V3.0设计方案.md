# 仓储 V3.0 设计方案

> 定位：把《仓库AI应用实施计划》7+6 共 13 项应用从"半实现/未动"补齐为**整项闭环**——
> 飞书为闭环操作端（手机端约束的落点）、Bitable 为台账权威、本地平台为分析展示与对账层。
> 设计输入：飞书计划文档（revision 26）+ V1.0/V2.0 完成度盘点（约 1/3）+ 2026-09-17 四项架构定案。
> 日期：2026-09-17。

## 一、完成度基线（V1.0+V2.0 后）

两期格局：**录入半边**扎实（送货单识别/GMP与成品出库对话登记，V1.0 落地）；
**分析半边**由 V2.0 平台补齐（周转/呆滞/补货建议/月报/对账/驾驶舱）；
**闭环半边**（推送、确认审批、QC 流程、外部衔接）两期均未启动。

| 计划项 | 现状 | V3.0 目标 |
|---|---|---|
| 原辅料① 入库录入+请验放行闭环 | 录入✅ 闭环❌ | 闭环全链路（V3.0 旗舰） |
| 原辅料② 领料先进先出匹配 | 未动 | 对话发起+匹配+确认卡 |
| 原辅料③ GMP出库智能录入 | 对话登记✅ 拍照❌ | 维持对话登记（拍照不做，见第七节） |
| 原辅料④ 供应商名录与准入 | 未动 | Base 名录表+准入确认门 |
| 原辅料⑤ 流转周期与库存健康 | 分析✅ 推送审批❌ | 清单推送+处理方案确认门 |
| 原辅料⑥ 使用分析与合理化建议 | 弱化实现 | 月度对比分析报告推送 |
| 原辅料⑦ 汇总与库存报表 | 月报✅ | +年报/危化品专项/周报推送 |
| 成品① 入库录入+ERP衔接 | 未动 | 成品入库单识别场景；ERP 暂缓（3C） |
| 成品② 出库录入+快递号识别 | 对话登记✅ | 快递通知自动化 |
| 成品③ 库存实时与周期汇总 | 实时✅ | +每日/每月汇总推送 |
| 成品④ 退货/不合格/待处理闭环 | 只读接入 | 聚合推送+处理方案确认门 |
| 成品⑤ 发货去向与代理商分析 | 未动 | 月度分析报告推送 |
| 成品⑥ 开票发货闭环 | 未动 | 四态聚合推送（Base 建列） |

## 二、架构定案（2026-09-17 拍板）

| 决策 | 选择 | 设计含义与代价 |
|---|---|---|
| 审批载体 | **1C 确认卡降级** | 不建审批流引擎；"处理方案审批"= 飞书确认卡二值确认（确认/取消）+ 回写 Base 字段 + 审计记录。对外口径统一称"线上确认"。无多级会签/驳回分支。 |
| 台账权威 | **2B Bitable 为权威** | 闭环状态（QC/处理方案/冻结）以 Base 字段为事实源；本地一切状态类写操作**先写 Base、成功后落本地镜像**；对账中心裁决反转为 **Base 胜出**；分期D 本地库存状态机降级为"操作镜像+展示"，不再单方面写。 |
| ERP 衔接 | **3C 暂缓** | 成品①的 ERP 部分标注"依赖外部系统，挂起"；识别录入部分照常交付。 |
| 手机端 | **4A 飞书端优先** | 所有闭环操作卡片/对话化，手机飞书即移动端；Web 维持桌面优先。卡片文案按窄屏排版约定。 |

四个决策方向一致：**回归计划文档原始定位**——以飞书多维表格为中枢做应用闭环，本地平台不扩权威、只做分析展示与对账。

## 三、闭环基座（三件新基建）

### 3.1 推送订阅中心

- 新模型 `WarehousePushTask`（任务名/scene/内容模板参数/目标 chat_id 或 open_id 列表/频率 fixed_time 或 interval/窗口守卫/启停）+ `WarehousePushLog`（每次推送结果与失败原因）。
- 内容生成器**只复用现有聚合函数**：morning_report、reports（月报/周转/消耗）、intelligence（异常/清单）、成品聚合（新增）。LLM 摘要沿用白名单校验+降级文案（宁夏模式）。
- 管理页：系统配置中心新增"推送任务"Tab（ops_config scheduler_registry 同款 CRUD+审计模式）。
- 上线任务：晨报推群（补 V2.0 欠账）、周库存报表（周一 08:30）、月报推送（月初）、超6月/不合格清单（每日）、成品每日汇总、月度分析报告。

### 3.2 通用确认门（确认卡即审批）

- 新模型 `WarehouseConfirmRequest`：business_type / ref_key（Base 表+record_id）/ payload 快照 / 目标（chat 或 user）/ 状态机 pending→confirmed|cancelled|expired（含重发）/ TTL / 回写字段映射（字段名→值）。
- 实现：从 draft_flow 状态机抽通用版——登记场景继续走 AgentDraft，**业务确认**（放行确认、处理方案确认、准入确认、领料批次确认）走 ConfirmRequest；复用确认卡 PATCH 状态推进、防重复、超时重发三件套。
- 确认动作 = 按映射**回写 Base 字段**（单选/人员/时间）+ 记审计 + 回执卡。取消动作 = 只记结果不改数。
- 口径限制（随 1C 定案声明）：二值确认、单级、无会签；被确认人可在 Base 直接改数——确认门是加速器不是闸门（与 2B 一致）。

### 3.3 Bitable 权威落地

- **写路径统一**：新 helper 统一"先 Base 后镜像"事务语义（Base 成功→本地镜像；Base 失败→整体失败）。涉及存量改造：库存状态变更（web_stock_status）、效期自动冻结（expiry_freeze）——冻结动作改为回写 Base QC 状态字段，本地冻结标记仅展示。
- **对账裁决反转**：reconciliation 差异默认 Base 胜出，生成"本地修复"动作项；三态视图保留人工复核。
- **生产版切换**（横切，参照安全模块直读改造经验）：bitable_config 增加生产版表坐标配置组 + 环境开关；切换前双路径逐日比对逐字相同 + 零回写探针，再切生产。

## 四、逐项闭环设计

### 4.1 原辅料① 请验放行闭环（旗舰）

Base 字段**已齐**（base_scan 快照实测）：请验单(附件)、QC取样情况(已取样/未取样/无需取)、QC出报(已出报合格/不合格/未出报/免检物料)、QC报告单、QC出报人、QA放行(放行/否决/条件放行)、QA放行人、放行提交时间、有效期至/复验期至。**无需 Base 建表建列**，只做应用层：

1. **入库登记确认后** → 自动推 QC 群"到货请验"卡（物料/批号/供应商/请验单附件链接）；
2. **扫描**（每 60min，窗口守卫）：未取样超 N 天 → 提醒 QC；未出报超全检周期阈值 → 加急标识提醒（阈值走预警规则中心，物料级可覆盖）；
3. **QC出报=合格** → 推 QA 确认门 → 确认后回写 QA放行+放行人+放行提交时间 → 推仓库群"批号 X 已放行可上架"；**否决** → 自动生成不合格记录 + 确认门（处理方案）；
4. **状态全流程跟踪**（入库/请验/检验中/放行/不合格）：QC 状态字段轮询镜像到本地库存列表与驾驶舱待办流（只读展示）。

### 4.2 原辅料② 领料先进先出匹配

- 入口：飞书对话（"精制一部领料 XXX 500Kg"→ LLM 收集物料/数量/领用部门——领用部门选项集已存在）。
- 匹配引擎（本地现算，无新表）：读 material_stock 该物料 **QA放行** 批次，按入库时间升序生成 1..N 批号建议（跨批拆分）；无放行批次/库存不足 → 明确 error 分支。
- 确认门给仓管员（可改批号）→ 确认后写 material_outbound 台账。

### 4.3 原辅料④ 供应商名录与准入

- Base 新建**供应商名录表**（编码/名称/审计状态/准入日期/状态）——唯一需要 Base 建表的票。
- 准入流：采购发起（对话/表登记）→ QA 确认门 → 回写名录状态。
- 入库识别供应商与名录比对（aligner 已提取该字段）→ 不一致推提醒卡；"AI 辅助核对"= LLM 一致性提示，不做判定。

### 4.4 原辅料⑤⑥ 补全

- ⑤：超6月/不合格清单（dead_stock/unqualified_stock 表已接入）→ 每日聚合推送 + 处理方案确认门回写；车间周用量计划先做简化版——阈值推送目标化（推到指定群/人），"按车间用量计划"维度列为远期。
- ⑥：物料月度预期用量基准（名录列）→ 月度"实际 vs 预期"对比分析报告（LLM 解读+合理化建议）推送；"自动回填"降级为"报告+人工采纳"（1C 口径）。

### 4.5 原辅料⑦ / 成品③ 报表补全

年报（月报聚合）、危化品/易制毒/易制爆专项报表（物料分类标记 + 导出）、周库存报表与成品每日汇总推送——全部进推送订阅中心。

### 4.6 成品① 成品入库识别

recognizer 新增 finished_receipt 场景（成品入库单 prompt：品名/批号/数量/单位/生产车间）→ 写成品产销存 Base。ERP 部分标注暂缓（3C）。

### 4.7 成品② 快递通知自动化

出库登记含快递号 → 确认后**自动**推发货通知卡到配置目标（销售/客服群），不再要求回复 group:/user:；交互指令保留为兼容。

### 4.8 成品④⑤⑥

④：退货/不合格/待处理每日聚合推送 + 处理方案确认门；
⑤：sales_detail 月度聚合 → 发货去向/代理商排名/销量对比报告推群；
⑥：成品销售汇总 Base 建开票相关列 → 每日"开票/未开票/开票未发货/发货未开票"四态聚合推送。

## 五、工程支撑清单

- **新模型（本地，全部为配置/确认/日志，无业务权威表）**：WarehousePushTask、WarehousePushLog、WarehouseConfirmRequest（+审计）。
- **新端点**：推送任务 CRUD+手动触发；确认单列表/统计/重发；QC 状态镜像查询；领料匹配预演；报表新增 4 个（年报/危化品专项/发货分析/开票聚合）。
- **新定时任务**（全部窗口守卫+互斥）：QC 进度扫描每 60min；清单/汇总推送每日；周报周一、月报月初；开票聚合每日。
- **Base 侧工程票**：供应商名录表（建表）、开票列（建列）、生产版坐标梳理与切换（横切）。

## 六、分期路线图

| 阶段 | 内容 | 周期 | 验收标准 |
|---|---|---|---|
| **A 闭环基座** | 推送订阅中心+确认门框架；先 Base 后镜像改造；对账裁决反转；晨报/周报/月报/清单推送上线；快递自动化 | ~1.5 周 | 晨报送达飞书群；一次处理方案确认门走通回写 |
| **B QC 请验放行** | 4.1 全链路+状态镜像+全检周期阈值 | ~2 周 | 一批物料从到货到放行全程无人工查询、提醒按期到达 |
| **C 匹配与供应商** | 领料 FIFO、供应商名录准入、成品入库识别 | ~1.5 周 | 一次领料对话完成 FIFO 匹配确认入库 |
| **D 分析补全+生产切换** | 成品分析/开票/专项报表/年报；生产版切换双跑 | ~1.5 周 | 四态开票推送上线；生产 Base 双跑比对零差异 |

## 七、明确不做（V3.0 范围外）

正式审批流引擎（1C 定案）；ERP API 直连（3C）；本地权威状态副本（2B）；Web 移动端专属页（4A）；采购模块实体化（procurement 空壳不动，采购申请走确认门）；GMP/成品出库拍照识别（对话登记已满足，识别投资留给入库场景）；库存预测时序模型（远期）。

## 八、部署与风险

- **生产部署**：本地镜像库从零冷启动（首日全量拉 Base 快照建镜像）；配置全部走系统配置中心/settings，不依赖本地文件——本地开发与服务器生产的差异只剩 Base 坐标（测试版/生产版配置组）。
- **Bitable 限流**：轮询任务增量拉取（按修改时间）+ 窗口守卫；推送失败走 failure_notifier 既有通道。
- **口径风险**：确认卡≠正式审批（1C），对外统一"线上确认"表述，需仓储部认可并回填计划文档进度说明列。
- **数据质量**：2B 下分析质量取决于 Base 填写质量——对账中心周报兜底，差异项进驾驶舱待办。
