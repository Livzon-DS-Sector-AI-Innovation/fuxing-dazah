## 范围（=设计文档 §十一 一期，不得扩大/缩小）

### M1 数据底座+库存引擎（~2 天）

- `backend/app/modules/warehouse/hardware/` 子包（models/schemas/service/api/importer.py，按需 scheduled.py）
- **一期只建 7 张表**：`hardware_materials` / `hardware_locations` / `hardware_receipts` / `hardware_receipt_items` / `hardware_requisitions` / `hardware_requisition_items` / `hardware_movements`（schema=warehouse，前缀 hardware_；字段定义照设计文档 §二）
- ⚠️ **坑**：warehouse 的 models 在模块根单文件（`warehouse/models.py`），子包 models 必须在 `backend/alembic/env.py` 的模型发现清单**显式 import**，否则迁移漏表
- 492 项清单导入器（管理端上传或 CLI seed 二选一）：类别/名称/规格/单位 + 安全库存 + 5 部门月需求(monthly_demands JSON) + 采购周期；code 全留空
- 库存口径 service：`available = on_hand − reserved`；预扣(pending)/释放(rejected/cancelled)/实扣(issued)；FIFO 按 `receipt_items.remaining_quantity` 批次分配（arrived_at 升序）；**库存变动收口**：只随入库单 accepted 与出库单 issued（+二期盘点调整），无单据不动账
- REST API 挂 warehouse 子 router → `/api/v1/warehouse/hardware/*`；权限码 `warehouse:hardware:<resource>:<action>` 进 `warehouse/permissions.py`
- 前端库存总览页：`frontend/src/app/(dashboard)/warehouse/hardware/page.tsx` 薄壳 + `components/warehouse/hardware/` 组件 + `lib/api/warehouse-hardware.ts`（SERVER_API/CLIENT_API 双基址模式照抄 `lib/api/warehouse.ts`）；菜单挂「仓储管理」组
- agent 工具 `query_hardware_stock` 挂仓库 agent：`warehouse/agent/tools/` 新文件声明 TOOL_FUNCS/TOOLS 并入 `query.py` 聚合字典

### M2 OCR 入库链（~2-3 天）

- 新场景 key `hardware_receipt_recognition` 注册进 `warehouse/ai_config/scenario_registry.py` 的 `_SCENARIO_FUNCTIONS`（vision/feishu），继承模型选路+场景开关+审计
- 识别链**复用现有 receipt_recognition 管线骨架**（图片方向预判+字段识别，同模块已有）：送货单照片 → 结构化 JSON（供应商/单号/到货日期/多行 品名+规格+数量）
- **四级主数据匹配器**（独立可复用模块）：code 精确 → 名称+规格模糊 → 同义词 → 人工兜底；每行输出匹配置信度，低置信标黄、**只标记不代改**
- 入库流程：draft（草稿）→ 一屏确认（仓管员+使用部门经办双确认）→ accepted（**stocked 共用类**：生成批次+movements+库位+物料卡；**direct 车间单独需求类**：出入双流水净零不占库存+target_dept 领取卡推送）/ rejected（留证+通知采购）
- 兜底 manual 登记（表单：选物料/数量/拍照留证，source=manual 单列可查）
- 前端入库台（出入库工作台页 `/warehouse/hardware/inout`）；agent 对话入库（发照片→草稿回显→两段式确认卡，复用 `warehouse_agent_drafts` + `confirm_requests` 确认门）
- direct 领取卡通知走 push_center generator 注册或 notification

### M3 领料审批闭环（~2 天）

- `backend/app/platform/integrations/feishu/approval.py` **新增** `create_instance`（POST /open-apis/approval/v4/instances，uuid 幂等；凭证走 safety 应用 env——2026-10-28 已拍板口径；现有只读方法 list_instance_codes/get_instance 语义不动）
- **审批双通道**（definition code 业务部门尚未建，保留通道）：`ApprovalChannel` 抽象，`feishu` 实现（definition code 从 env/配置读，未配置=不可用）/ `manual` 实现（部门主管在领用中心点确认=审批结果代录）；工厂按配置选择，**状态机对通道无感**
- 领料状态机：draft→pending(**预扣**)→approved→issued(**实扣**)/rejected(释放)/cancelled；req_type normal/urgent/excess；紧急 24h 未补单提醒（TaskDefinition 定时注册 main.py lifespan）；超额在审批环节提示需生产总监（manual 通道落审批备注）
- 前端领用中心页（发起：物料搜索+库存可见/我的申请/部门月度统计）+ 发料台（待发料+FIFO 建议批次+实发量确认+领用人点收）
- feishu 通道审批结果轮询兜底：复用 list_instance_codes 增量拉取

## 硬约束（违反=返工）

1. 分支：feature/warehouse-module 唯一分支，直提直推，**禁止新建任何分支**
2. 不动原辅料/成品域（Bitable 2B 权威模式）与 safety 模块既有行为；approval.py 只增不改
3. 复用优先（禁新建平行基建）：scenario_registry / receipt_recognition 管线 / 两段式草稿+确认门 / push_center / agent tools 聚合 / TaskDefinition
4. ERP 零依赖：movements 带 erp_status(pending/entered) 字段即可，不建任何 ERP 连接；编码表 Excel 导入器+code 回填 CLI 建好待文件（通道保留）
5. **stocked 类入账/出账必经人确认**——OCR/agent 只产草稿，永不自动动账
6. 数量精度 Numeric(18,3)；时区 Asia/Shanghai；movement.quantity 恒正 + direction 表方向
7. 开发环境：`backend/.venv/bin/python` + pytest；开发库 dazah；alembic 手写建表迁移（含 downgrade），命名 `<12位hex>_hardware_store_p1_tables.py`

## 验收（每里程碑完成即自验，全部通过才算完成）

- **M2**：以合成样例图+单测验收识别链与四级匹配逻辑（真实送货单实测由用户验收阶段补充，交付报告标注）；OCR 只产 draft 不动账（断言）；direct 直发推送到达测试群；低置信标黄人工修正后入账
