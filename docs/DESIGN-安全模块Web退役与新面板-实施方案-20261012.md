# 安全模块 Web 退役与新面板实施方案（3.0）

> 日期：2026-10-12
> 代码基线：fuxing-dazah @ b5e49398（feature/warehouse-module）
> **本方案口径（2026-10-12 拍板，取代前两案的分期）**：
> 1. 联动编排/督办等新引擎**推迟到最后打磨**（前两案的设计保留作远期参考，不进当前排期）；
> 2. **不做业务多维表格迁移**——正在开展的业务已对接多维表格；没有对接的说明业务不开展，**页面与后端一并退役**；
> 3. 当务之急：**退役旧 Web 功能 → 按矩阵体系要素上全新面板**；
> 4. AI 审计与配置系统**保留并简化**，参考仓储模块（2.0 理念），升级为 3.0。

## 0. 一句话定位

安全模块前端推倒重排：**菜单按 GB/T 33000-2025 体系要素分组、17 个体系模块各一个界面（纯文字命名，不带编号）**（已开发的复用改造、未开展的灰显占位、无表格对接的退役）；新增**总览驾驶舱**；配置与审计**合并为仓储同款单页**。页面全部是**只读监控视图**（数据来自多维表格直读），业务操作不回 Web。改造分三期明确推进（§5）：一期退役+框架、二期驾驶舱、三期配置合并+打磨。

## 1. 第一步：旧 Web 功能退役清单

### 1.1 退役判据

- 页面承载的业务**无多维表格对接**（平台自建表/状态机）→ 业务不开展，页面+后端一并退役；
- 页面只是表格业务的"流程包装"（登记向导/详情流转），台账查询已有 → 退役流程页、保留台账页；
- 交互已由机器人全量承载（URS/知识问答）→ 退役 Web 入口。

### 1.3 后端退役与前置检查

**退役前统一跑引用盘点**（grep API 端点在 Agent 工具/定时任务/其他模块的引用）：

| accidents / checks / trainings / regulations(+revisions) / contractors / daily_risk_reports / special_ops_personnel | 删除 | Agent 工具无直接引用（工具走 service 层）；确认无定时任务读 |

## 4. 系统配置与审计简化（参考仓储 2.0，单页 Tabs）

现状 6 个菜单页（ai-config / bitable-config / app-config / scheduled-tasks / ai-audit / agent-chat）→ **合并为 /safety/system 单页**，对齐仓储 SystemConfigPanel 形态：

| Tab | 内容 | 来源 |
|---|---|---|
| AI 模型 | 模型接入/探活 | AiConfigPanel 拆出 |
| AI 场景 | 场景-模型路由/熔断 | AiConfigPanel 拆出 |
| 多维表格 | 14 域连接/字段映射/测试 | BitableConfigPanel 原样 |
| 定时任务 | 任务列表/开关/报告预览 | scheduled-tasks 页并入 |
| 应用配置 | SAFETY_* 运行参数 | AppConfigPanel 原样 |
| AI 调用审计 | 调用流水/统计/详情 | AiAuditPanel 原样 |

简化点：菜单 6 项→1 项；组件基本现成（都是 Panel 组件，改 Tab 容器即可）；沿用仓储 `配置变更实时生效` 的交互口径（app_config 本就免重启）。

## 5. 分期实施计划

三期推进，每期独立交付、独立验收；联动编排等新引擎不在本期范围内（后续期另立项）。

### 一期：旧功能退役 + 新框架（约 1 周）

| 项 | 内容 |
|---|---|
| 范围 | ① §1.2 全部 15 项页面退役 + §1.3 后端路由删除（引用盘点前置）；② menu-config.ts 重写为体系要素分组（纯文字）；③ 4 个占位页（目标责任/教育培训/设备设施/事故事件）；④ 危化品与MSDS、监测报警两个合并双 Tab 页；⑤ EHS 变更页台账化（去状态机操作按钮） |
| 交付物 | 新菜单 + 干净的路由面 + 占位/合并页 |
| 出口标准 | 退役页 404 且菜单无残留；新菜单全量生效；回归全绿（后端既有基线 + 前端 build/test）；每项退役独立 commit、可单独 revert |
| 前置 | §1.3 引用盘点脚本跑完并落档 |

### 二期：总览驾驶舱（约 1 周）

| 项 | 内容 |
|---|---|
| 范围 | ① 后端 `GET /safety/overview` 聚合端点（隐患/特殊作业/消防/中控/持证/危化品 stats + 速递存档）；② 驾驶舱页（§3：KPI 行、速递流、趋势图、健康度卡片墙、下钻三列） |
| 交付物 | /safety 新门面（替换旧 SafetyDashboard） |
| 出口标准 | 一次拉取 <2s；各指标与对应域 stats 端点抽样一致；健康度墙 17 个模块全展示、灰卡点击达占位页 |
| 前置 | 一期完成（菜单与页面结构稳定） |

### 三期：配置中心合并 + 模块页统一打磨（约 1-2 周）

| 项 | 内容 |
|---|---|
| 范围 | ① /safety/system 六 Tab 单页，旧 5 个配置页 301；② 11 个复用页统一仓储套件视觉（StatCard/SectionCard/QueryFilter）并强化统计；③ 人员资质页强化为证书台账+预警一体；④ 全流程监督页起步（作业票审核记录+违规明细查询） |
| 交付物 | 配置单页 + 统一视觉的全模块页 + 监督页 v1 |
| 出口标准 | 旧配置页 301 生效；模块页视觉统一抽检通过；监督页可按日期查审核摘要与违规明细 |
| 前置 | 二期完成 |

### 后续期（另行立项，不占本次排期）

- **联动编排与督办**：事件总线、联动规则引擎（报警→隐患等）、督办状态机、飞书审批流——按前两案设计择期启动；
- **占位模块启动**：设备设施管理（设备台账先行）、目标责任与绩效、教育培训与行为管控、事故事件管理——按业务开展需要逐个立项，建表格对接后替换占位页。
