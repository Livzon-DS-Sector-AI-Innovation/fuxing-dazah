# 外部审计隐患通报 — 督办通报扩展设计（2026-10-21，拍板修订版）

## 0. 需求与拍板结论

需求：在现有隐患督办通报基础上新增「外部审计隐患通报」，外审缺陷项**未关闭即红色预警**。

拍板口径（2026-10-21 用户确认）：

1. **并入现有督办格子**（`hazard_bulletin`），**不新增速递格子**；节奏完全随督办
   （周四 13:00 首发 + 13:00-18:00 值守轮询，值守比对自动覆盖外审变化）；
2. 「推送到群」按钮**同原来的督办**（同格同按钮同目标群，零改动）；
3. **已关闭项不再追踪**（同原督办：明细不列，只在统计行计数）；
4. **不看目标期限**：未关闭 = 红色预警，已关闭 = 不督办。不做逾期/剩余天数判定。

> 展示名修订（2026-10-22 拍板）：通报内所有「外部审计隐患／外审」文案统一改为
> 「管委会隐患」（当日两拍：先「管委会审计隐患」再去「审计」二字），覆盖节标题、
> 顶部统计行、部门汇总行、速递格子「含管委会隐患 N」、收口行。代码域名
> `external_audit_hazard`、文件名 `external_audit.py` 与 registry 配置键**不改**
> （DB 播种键，改名断源）。
>
> 整改中口径修订（2026-10-22 拍板）：「整改状态=整改中」与主表同口径**不预警**
> ——不进明细、不计入未关闭/部门汇总，仅收口行计数（无未关闭时收口行并陈
> 「已关闭 N 条，整改中 M 条」）；未关闭=红色预警的判定不变。

扩展性口径：本数据源（江阴管委会缺陷项汇总）只是第一个外审源，后续新外审源
**采用一样的模式**接入（registry 新 kind + 同款 reader），红色预警判定标准固定为
「未关闭即红」，与内部督办（按督办等级判定）并存于同一通报。

## 2. 总体架构：并入 hazard_bulletin 格子

```
内部隐患主表（现有，不动）                外审缺陷项汇总表（新）
        │ _fetch_targets                        │ strict 全量直读
        ▼                                       ▼
hazard_direct/bulletin.build_bulletin   hazard_direct/external_audit.py
        │                                       │ 未关闭→🔴红（唯一规则）
        └──────────────┬────────────────────────┘
                       ▼
        同一份 markdown：内部节 + 「外部审计隐患」节 + 合并部门汇总
                       ▼
        deliver_bulletin → upsert_daily_digest("hazard_bulletin")（现有格子）
                       ▼
        周四 13:00 任务 + 值守轮询 + 推送到群按钮（全部现有机制，零改动）
```

关键性质：

- **外审缺席时输出逐字节等于现状**（源未配置/停用/读取失败 → 外审节整体缺席，
  内部部分一字不改）——值守轮询按整格 detail 逐字比对，不会因本次上线产生误刷新；
- 内外两源读取/渲染各自独立 try/except，外审源故障只告警，不影响内部督办投递；
- 值守轮询、推送到群按钮、调度任务行、前端驾驶舱回放：**全部零改动**（同格）。


## 3. 后端改造点

### 3.1 bitable_config 注册新域（registry.py）

第 20 域，照 visitor_notice 模式（纯只读、无事件订阅、`subscribe="record"`）：

```python
DomainInfo(
    key="external_audit_hazard",
    label="外部审计隐患",
    purpose="外审缺陷项汇总表（督办通报外审节直读源；未关闭即红色预警）",
    subscribe="record",
    kinds=(
        KindInfo(
            kind="defect_summary",
            label="外审缺陷项汇总表",
            default_connection=DefaultConnection(
                app_token="R8uBb4OBQanS95sXcgjcW9HbnEe",
                table_id="tbl9RjRjKMeo6B1b",
                note="江阴管委会安全检查缺陷项汇总",
            ),
        ),
    ),
)
```

- **无需播种迁移**：registry `default_connection` 即运行时 fallback（DB 无行时
  status=default 直接生效，与 visitor_notice 先例一致）；DB 行可经 bitable 配置页
  改值/停用（停用 = 外审节整体缺席）；
- **后续新外审源**：同域加新 KindInfo（一源一 kind，连接独立可停），
  reader 复用同一套字段名；若新源表字段名不同，在该 kind 上加字段名覆盖。
  前端 bitable 配置页 registry 驱动，自动多一张域卡，零改码。

### 3.2 hazard_direct/external_audit.py（新文件）

- 字段常量 + `REQUEST_FIELD_NAMES` 投影（只请求消费列，对齐 visitor_insurance）；
- `ExternalAuditView`：`record_id / seq / description / plan / departments /
  closed / checked_at / target_date / responsible[(name, open_id)]`；
- 状态映射：`已关闭 → closed`，**其余（未关闭/空/异常）→ open**（字段默认值就是
  「未关闭」，从宽判定不漏报——拍板 4 的落地）；
- `fetch_external_audit() -> list[view] | None`：`resolve_client` 抛
  BitableConfigError（未配置/停用）→ None；否则 strict 全量拉取（量级 11 条）；
- `build_external_section(views, person_at) -> (list[str], dict)`：
  渲染外审节 + 统计（`ext_open / ext_closed / ext_depts`）；
- `harvest_responsible_ids(views)`：直取人员字段 open_id（同 bulletin
  `_harvest_person_ids` 口径，读取应用作用域，无需 identity 回退）。

### 3.3 bulletin.py 并格集成

`build_bulletin()` 组装顺序：

```
【隐患督办通报】
━━━━━━━━━━━━━━━━━━━━
📅 date
🔴 红色预警 X 条 · 🟡 一般预警 Y 条 · 涉及 N 个部门      ← 内部统计（原有）
[⚠️ 未更新进展 M 条]                                       ← 原有
[· 外审未关闭 B 条]                                        ← 新增（B>0 时追加）

<内部部门分组红色预警明细>                                  ← 原有不动

━━━━━━━━━━━━━━━━━━━━
📌 外部审计隐患（未关闭即红色预警）
━━━━━━━━━━━━━━━━━━━━
🔴 未关闭 **4** 条 · ✅ 已关闭 7 条 · 涉及 **3** 个部门

**提炼工程二部（1条）**　@蔡万进
**1.** 酸碱罐区储存设施，已在做设计诊断，未见设计诊断报告。
方案：设计院安全设计院诊断中，诊断报告预计10月底出
检查：2026-10-19（N 天）｜目标：2026-10-31｜[📋 查看记录](记录链接)
…

━━━━━━━━━━━━━━━━━━━━
📌 各部门未关闭隐患数量汇总
━━━━━━━━━━━━━━━━━━━━
**部门**：红色预警 X 条 [+ 一般预警 Y 条] [+ 外审未关闭 Z 条]   ← 外审并入同表
```

细则：

- 外审明细行：描述 + 方案（空则省行）+ 检查日期（含发现至今天数）+ 目标日期
  （**纯展示，不做逾期判定**——拍板 4）+ 记录链接（app_token/table_id 取自连接）；
- 部门分组 @ 责任人（人员字段直取）；部门名走 `DEPT_NORMALIZE` 归一，
  与内部汇总部门可合并同键；
- 排序：部门按未关闭数降序；条目按检查日期升序（老的在前）→ 序号；
- 外审全部关闭：节内仅一行「✅ 外审缺陷项已全部关闭（累计 N 条）」；
- 内部为空且外审有未关闭：**不走原「今日无预警」早退**，正常出外审节；
  内部为空且外审也全关：原「今日无」文案 + 外审全关闭一行；
- 外宣 stats 新增 `ext_open / ext_closed / ext_depts`；
- `deliver_bulletin` 格子概览统计行（外审缺席时保持原文案逐字节不变）：

```python
未关闭 **{total + ext_open}** 项 ｜ 🔴 红色预警 {urgent + ext_open}（含外审 {ext_open}）· 🟡 一般预警 {warning}
```

## 4. 与现有体系的边界与防重

- 内部格子继续用 `is_audit_record`（管委会/审计/政府/应急局关键词）排除主表外审
  记录——内外两源天然互斥，不会双计；
- 外审表只有已关闭/未关闭两态，无「整改中」歧义；
- 外宣格红色预警计数 = 内部督办等级红 + 外审未关闭，口径在统计行显式标注
  （含外审 N），读者不混淆。

## 5. 风险与开放点

| 风险 | 应对 |
|---|---|
| 表按批次复用，将来新建独立表 | 同域加新 kind 或 DB 改连接值，不动代码 |
| 外审来源多元化（不止管委会） | 条目带检查日期；确需区分来源时加「检查来源」列，reader 补一列 |
| 未关闭项长期挂账每周重复曝光 | 需求本意（未关闭=红）；全关闭后转正向收口行 |
| #5 型脏数据（未关闭却填实际完成时间） | 关闭判定只看整改状态字段，已钉死 |
