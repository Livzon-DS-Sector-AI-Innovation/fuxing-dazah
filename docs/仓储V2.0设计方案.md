# 仓储 V2.0 设计方案

> 定位：把仓储从 V1.0 的"事务记录系统"升级为**带完整前端的智能仓储运营平台**——
> 看得清（可视化）、管得住（全流程）、猜得到（预警与建议）、问得动（AI 助手）。
> 设计输入：本地 V1.0 现状 + 宁夏 Livzon-NX 仓储考察（学它的产品原型与交互范式，不学它的工程债）。
> 日期：2026-09-15。

## 一、V1.0 现状基线

**后端**（20 端点 + 配置中心）：物料/库位/库存/出入库/盘点五组 CRUD + 概览统计；
系统配置中心（AI 模型/场景/运行参数/Bitable 连接/定时任务 + 五类审计）；
Agent 子系统（**仅飞书 IM 入口**：送货单图片识别 → 主数据对齐 → 草稿 → 人工确认 → 写回 Bitable；技能 .md 热加载）；MCP 只读查询。

**前端**（5 页 19 组件）：首页仅重定向到库存页；库存页 = 5 张静态统计卡 + 低库存 Alert + 三个表格 Tab；出入库、盘点为标准列表；系统配置中心已较完整。

**能力缺口**：无趋势图与库位可视化、无库存历史快照（算不了库龄/周转）、预警只有低库存一种、AI 助手只在飞书里（Web 端用户用不到）、本地与飞书无对账视图、盘点无差异分析视图。

## 三、逐页设计

### 1. 驾驶舱（对标宁夏 WarehouseDashboard + 我们的数据做增量）

- **KPI 行（5 卡，带趋势箭头）**：库存总量（环比）、今日入库/出库（对比昨日）、待处理预警数（点击跳异常检测）、进行中盘点数。数据源：升级 `GET /overview` 返回环比字段。
- **出入库趋势**（近 30 天 line，入/出双序列，悬浮显示单日单据数）：新端点 `GET /dashboard/movement-trend?days=30`。
- **库存分布**（按物料分类 pie + 按库区 bar）：`GET /dashboard/stock-distribution`。
- **低库存/呆滞 Top10**（bar，点击条目下钻到对应筛选的库存列表——**图必须可下钻**，这是宁夏仪表盘没有做好的点）。
- **库位利用率**（库区维度横向进度条或热力图，数据来自库位地图）。
- **待办与预警流**（右侧时间线组件）：低库存、临期、盘点任务、AI 待确认事项，每条可点击处理。
- **AI 摘要条**：顶部一句 LLM 生成的当日摘要（"今日入库 12 笔，3 项物料低于安全库存，建议关注…"），走白名单校验 + 降级文案（宁夏 inspection_progress_ai 模式：枚举回退、长度截断、失败给规则文案）。

### 2.1 现有库存（升级）

- **列扩展**：增加 库龄、批次/效期倒计时、物料状态（正常/待检/冻结/呆滞，语义色 Tag）、最近流水时间。
- **行详情 Drawer**（宁夏"只读 Drawer + Descriptions"范式）：物料基础信息 + 该物料近 90 天流水时间线 + 状态变更历史（依赖新模型 MaterialStatusTransition）。
- **筛选**：常驻（关键词/分类/库位/状态）+ "更多筛选"折叠（效期区间/库龄区间/有无批次），对齐宁夏偏差台账的两层筛选交互。
- **对比视图**：切换"本周 vs 上周"库存变化 Top（需日快照）。

### 2.2 库位地图（全新，可视化亮点）

- 库区 → 货架 → 库位三层钻取；库位渲染为格子，按占用率/物料分类着色，点击格子弹出该库位库存明细。
- 实现：CSS Grid 而非 canvas，数据 `GET /locations/map`（需库位模型补充 区/排/位 结构字段——**需确认现有 location 表结构**，若不支持则 V2.0 先按"库区分组统计 + 列表热力条"做平替）。

### 3.1 出入库作业看板（全新）

- 三列看板（今日待收 / 待发 / 已完成），卡片 = 单据，支持拖拽改状态（远期）；V2.0 先做"点击卡片 → 弹出登记表单预填"。
- 数据源：movements 按 `direction + occurred_at=今日 + source_type` 聚合。

### 3.2 快速登记（把 V1.0 的飞书 AI 能力搬到 Web）

- 入口按钮"拍照/上传单据"→ 调后端现有识别 pipeline（recognizer → aligner → draft）→ **草稿确认页**：左侧单据原图关键字段高亮，右侧对齐结果表（置信度低的行标黄），逐行确认/修改 → 提交。
- 这是把飞书里"发图片给机器人"的体验复制到 Web，是 V2.0 智能化最直观的卖点。
- 提交仍走 HITL：确认页本身就是人工确认环节，后端 `submit` 复用现有写契约校验。

### 4. 盘点管理（升级）

- **任务看板**：按状态（草稿/执行中/待确认/已完成）四列卡片，每卡显示进度（已盘 N/总数 M）。
- **差异分析**：确认前展示差异表（账面 vs 实盘，差异行标红 + 差异率），顶部差异汇总条形图；确认时强制填写差异说明（对齐"危险操作三要素"文案规范）。
- 后端：`GET /stocktakes/{id}/variance`（或确认页前端根据明细现算）。

### 5. 智能中心（全新）

| 页面 | 内容 | 智能点 | 后端支撑 |
|---|---|---|---|
| 异常检测 | 规则引擎扫出的异常列表（低于安全库存/零库存/负库存/长期无流水呆滞/临期），按类型 Tab | 每类异常顶部 LLM 解读条（白名单校验+降级） | `GET /ai/anomalies`（宁夏 ai_service 同款规则先行模式） |
| 补货建议 | 建议表：物料/当前库存/日均消耗/可支撑天数/建议采购量/到货周期 | 消耗速率回归 + 安全库存公式计算，LLM 只生成解释文案；**一键生成采购申请**（联动 procurement，走确认卡） | `GET /ai/replenishment` |
| 效期与呆滞 | 临期批次倒计时列表、呆滞物料排行（90 天无流水） | — | 快照表 + movements 聚合 |
| 每日晨报 | 当日 08:00 自动生成，Web 查看历史 + 推送飞书群 | 汇总异常/建议 | 定时任务 + `ai/daily-report` |
| AI 助手 | 右下角悬浮对话窗 | 查询/登记/分析，**Web + 飞书双入口共用后端 agent** | 见第六节架构决策 |

**AI 助手 Web 化（V2.0 核心决策）**：V1.0 的 agent 子系统入口是飞书 IM 事件；V2.0 给 gateway 增加 HTTP/SSE 入口（`/api/v1/warehouse/agent/chat/stream`），Web 悬浮助手与飞书机器人共用同一 Runner/工具/记忆/确认门。前端交互**直接对标宁夏 Livzon 助手**：
- 打字机流式输出 + "正在调用 xxx"阶段标签 + 停止按钮；
- 回复表格卡片化（查询结果卡 + "查看更多"）+ "数据依据"折叠区；
- **写操作确认卡三件套**：风险分级 Tag + 有效期倒计时 + 大白话后果说明，执行后回读验证（未落库提示"请勿重复写入"）；
- 附件白名单（单据图片走现有识别链路）。

### 6. 同步与对账（全新，补 V1.0 的暗账）

- **对账视图**：本地库存/流水 ↔ 飞书 Bitable 逐条比对（已同步/待同步/冲突三 Tab），冲突行展示两边值，人工裁决。
- **同步任务面板**：同步方向（本地→飞书）、上次成功时间、失败原因、手动触发/重试（借鉴宁夏 scheduled.py 的窗口守卫 + 互斥模式，方向反转）。
- 后端：`SyncLedger` 表 + `POST /sync/run` + `GET /sync/status`。

### 7. 报表中心（全新）

- 出入库月报（按月自动生成，可导出 Excel）、库存周转率 Top/Bottom、物料消耗排名、库位周转统计。
- **自然语言导出**（宁夏 SpecialOpsLedger 交互）：输入"导出 3 月所有出库到 201 车间的记录"→ 解析回显 → 下载 Excel，失败降级当前筛选。
- 定时报表推送复用现有 system-config 的 scheduler 任务配置。

### 8. 系统配置（沿用 + 扩展）

新增两个 Tab：预警规则（各异常类型阈值可视化编辑，改阈值需二次确认）、同步配置（飞书连接沿用现有 BitableTab + 新增同步策略项）。

## 五、后端与数据支撑（新增）

**新模型**（warehouse schema）：
- `StockDailySnapshot`（日快照：物料×日期×数量，趋势/周转/对比的数据底座）
- `MaterialStatusTransition`（状态变更日志，宁夏同款：diff 捕获 + occurred_at 取业务时间）
- `AlertRule` / `AlertRecord`（可配置阈值 + 异常记录）
- `ReplenishmentSuggestion`（建议 + 状态：待处理/已生成申请/忽略）
- `SyncLedger`（对账流水）

**新端点**（约 18 个）：dashboard 聚合 ×4、anomalies/replenishment/alerts ×5、agent HTTP 入口 ×2、sync ×3、reports ×3、locations/map ×1。

**新定时任务**（3 个，全部带窗口守卫与互斥，吸取宁夏 OOM/误触发教训）：
1. 每日 00:30 库存日快照（逐物料独立 session + gc 间隔）；
2. 每 30min 异常扫描（写 AlertRecord）；
3. 每日 08:00 晨报生成 + 飞书推送。

## 六、前端实现策略

1. **前置依赖**：先完成《仓储前端改造清单》P0/P1（测试设施、React Query 迁移、类型契约）——V2.0 所有新页面直接按新架构写，不背旧债。
2. **建立页面三件套封装**（吸取宁夏 200 个台账页无封装的教训）：`PageHeader`（标题+统计+操作区）、`QueryFilter`（常驻+折叠两层筛选）、`DataTable`（列定义+状态 Tag+分页+导出+空态三分法）。新页面全部基于三件套。
3. **设计规范**：沿用宁夏 DESIGN.md 的可取原则本地化——信息密度优先、表格为中心、空态区分"无结果/无数据/出错"、危险确认含对象+影响、主色沿用本地现有主题。
4. **图表**：统一 echarts（本地已有依赖），封一个 `ChartCard`（标题+时间范围+下钻回调）。

## 七、分期路线图

| 阶段 | 内容 | 周期 | 验收标准 |
|---|---|---|---|
| **A. 可视化基座** | 改造清单 P0/P1；驾驶舱；库存中心升级（Drawer/列扩展/两层筛选）；日快照模型+任务；出入库看板 | ~2 周 | 驾驶舱 6 个可视化块可下钻；库存详情时间线可查 |
| **B. 智能上线** | Web AI 助手（SSE+确认卡+卡片化回复）；快速登记（单据识别前端化）；异常检测+补货建议+预警规则配置 | ~2-3 周 | Web 端完成一次"拍照→识别→确认→入库"全流程；异常检测出报告 |
| **C. 对账与报表** | 同步对账中心；报表中心 + NL 导出；晨报；盘点差异分析 | ~2 周 | 对账三态视图可用；月报一键导出 |

**需先确认的决策点**：① location 表是否有 区/排/位 结构（决定库位地图做真地图还是热力条平替）；② 采购模块联动接口（补货建议一键生成采购申请）；③ 飞书对账以本地为准还是允许双向裁决。

## 八、明确不做的（V2.0 范围外）

PDA/扫码硬件对接、库内 AGV/自动化设备集成、多仓库/多组织、库存预测时序模型（列 V2.1）、移动端专属 UI（保持桌面优先，仅保证不塌）。
