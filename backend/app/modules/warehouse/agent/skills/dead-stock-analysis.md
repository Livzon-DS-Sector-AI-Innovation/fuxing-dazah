## 步骤
1. **规划**：这是多步任务，先调用 `plan_task` 制定计划（建议步骤：查询呆料清单 → 按物料大类分组 → 生成分组报告 → 经确认后逐个发送催办），之后每完成一步立即 `update_plan` 更新进度。
2. **查呆料**：调用 `query_report(report_type="dead")` 取呆料批次清单（入库总账中「呆料判断=是」的批次：物料名称/批号/入库数量/单位/入库日期/贮存位置/使用部门）。清单为空时如实告知「没有查到呆料记录」，把计划步骤标 done（note 注明无呆料）并结束。
3. **补齐物料大类**：`query_report` 结果不含大类，对清单中的物料名称去重后用 `query_material(keyword=物料名称)` 逐个补查「物料大类」；轮次预算有限时优先补查数量大的物料，查不到的批次归入「其他」并在报告中注明（也可参考贮存位置中的库名线索，如「原辅料库」「危化品库」）。
4. **分组**：把呆料批次按物料大类分组：原辅料 / 危化品 / 包材 / 中间体（无法归类的放「其他」）。班组长映射（**仅作为报告中的展示信息**）：原辅料-陈玉英、危化品-冷莉、包材-张亚丽、中间体-王朱宝、汇总-高跃庆。
5. **生成分组报告**：按「输出格式」生成报告，所有数字/批号/日期一律来自工具结果，禁止编造；开头给出各类批次计数汇总。
6. **展示并询问**：向用户完整展示分组报告，并询问是否催办。明确说明：真实催办需要用户提供各班组长的 open_id 或群 chat_id（系统没有班组长姓名到飞书 ID 的通讯录映射，无法自动转换）；用户未提供确切目标前，禁止调用 send_card、禁止猜测 ID。
7. **催办发送**（可选，仅在用户确认并提供确切目标后）：对每个目标调用一次 `send_card(target="user:<open_id>" 或 "group:<chat_id>", title="呆料处理催办", content=该组呆料清单要点)`；系统会向发起人发预览卡片，只有发起人点「确认发送」才会真正发出——在回复中提醒用户去卡片上确认，并把对应计划步骤更新为 done。

## 输出格式
分组报告按以下 markdown 结构输出（作为回复正文；用户要求发送时，send_card 的 content 也用同一结构）：

### 呆料分组报告（YYYY-MM-DD）
汇总：共 N 个大类、M 条呆料批次。

**原辅料**（班组长：陈玉英）

| 物料 | 批号 | 数量 | 入库日期 | 建议处理 |
|---|---|---|---|---|
| … | … | …（含单位） | … | 联系班组长安排领用/退库 |

（危化品-冷莉 / 包材-张亚丽 / 中间体-王朱宝 各一小节，结构相同；「其他」组不标注班组长。）

「建议处理」按批次情况填写（如：联系车间领用、安排退库、提报废申请）；日期类字段保持工具返回的 YYYY-MM-DD 原文，不得改写。
