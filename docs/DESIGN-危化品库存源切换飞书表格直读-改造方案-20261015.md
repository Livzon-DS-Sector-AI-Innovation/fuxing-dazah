# DESIGN — 危化品库存源切换：飞书《危险品日报表》直读（2026-10-15）

## 0. 一句话

危化品库存的数据源从「危险品日报群用户发 Excel → 后端异构解析 → 写 Bitable 总表」切换为**直接读取飞书电子表格《危险品日报表》**（13 子表按产品线/单元拆分），Excel 链路观察期后退役。

## 1. 背景

### 1.1 现有链路（legacy，全量保留至切换完成）

```
危险品日报群(oc_ae9c…) 用户发 .xls/.xlsx
  └─ 每天 19:30 scheduler「危化品库存日报」拉取当日文件消息
       ├─ excel_parser.py：12 套异构 sheet 解析器（列位硬编码 + 表头驱动兜底）
       ├─ daily_update.py::apply_daily_workbook：匹配 部门+存放部位+物料 → 写 Bitable 总表
       │    （app_token=QoUXbLVcQaYAO7sod1CcUH3JnVd, table=tbl78IlFOo3f1fj1）
       └─ 直读/镜像双路 → 风险规则 R01-R03 → 每日分析(vs 昨日快照) → 落快照 → 安全速递格子
（另有 realtime handler：群内文件消息实时驱动，2026-08-26 起默认关闭）
```

痛点：异构解析器 560+ 行补丁式演进（sheet 改名/列错位/内联单位都得跟）、Excel
靠人发（漏发=当天 no_files_today 跳过）、写回 Bitable 的匹配更新语义复杂（无删除、
行消失留脏行）。

## 2. 目标架构

**核心思路：新源不落 Bitable、不进 Excel 解析器——在直读层加一个
`SheetsInventoryReader` 实现，与现有 `InventoryBitableReader` 同协议
（`InventoryRecordsReader.fetch_all(strict)`），`open_reader()` 按源开关返回。**

下游（风险规则、每日分析、快照、速递、`/api/safety/chemical-inventory/*`、
驾驶舱 stats）全部零改动复用——这正是直读改造（Ticket 01-03）预留的注入点。

```
《危险品日报表》spreadsheet（人维护，唯一事实源）
  └─ SheetsInventoryReader（新）
       ├─ metainfo 枚举子表（跳过空表/Sheet12）
       ├─ 逐子表 read_sheet(<sheet_id>!A1:T60)（office_client 现成方法）
       ├─ 表头驱动列映射（危废库缺列自适应）→ InventoryView 列表
       └─ open_reader() 按 SAFETY_CHEMICAL_INVENTORY_SOURCE 开关注入
            ├─ 查询/统计/驾驶舱：CachedInventoryReader（TTL 300s）自动生效
            └─ 19:30 日报编排：strict=True 全量 → 内存风险重算 → 分析/快照 → 速递
```

与 legacy 的关键差异：
1. **19:30 任务不再拉群文件**：sheet 模式下跳过 `fetch_daily_files`/下载/`apply_daily_workbook`（Bitable 不再写），直接进入 `_finish_direct` 等价的收尾流程
2. **不回写源表**：风险标记/说明不写入人维护的 spreadsheet（WRITEBACK_RISK 在 sheet 模式强制视为关），风险值只在内存与快照里
3. **Bitable 总表冻结**为回滚兜底（只读不写），观察期后归档

## 3. 关键设计决策

### D1 源切换开关（gates 模式，默认关）

- 新增 `SAFETY_CHEMICAL_INVENTORY_SOURCE`，取值 `bitable`（默认，行为不变）/ `sheet`
- 实现为 `chemical_inventory_direct/config.py` 新增 `sheet_source_enabled()`，`open_reader()` 与 daily_job 分支同读此开关；与既有 `DIRECT_ENABLED` 正交（sheet 模式隐含 direct 语义：service 各读路径走 `open_reader()`）
- 电子表格连接进配置中心：`bitable_config` 新 connection `("chemical_inventory", "source_sheet")`，`app_token=H0YWsAf52hBAIDtmJlxcqThZn2c`（registry 默认值落库，wiki URL 仅注释）
- 回滚 = 开关拨回 `bitable`，一行不改

### D2 部门分类法：新子表=新部门枚举（additive）

旧枚举（仓储部/提炼一部/…）是**职能部门**口径，新子表是**产品线/单元**口径，二者不同维。
方案：`enum_maps.py` 新增 9 个枚举（替考/氟雷/米尔贝/溶媒回收/达托/达巴/艾默/雷帕/危废库），
slug 建议 `tikao/fulei/milbemycin/solvent_recovery/daptomycin/dalbavancin/aimo/rapamycin/hazwaste`
（具体英文 slug 拍板时可调），中文标签=sheet 名；旧枚举全保留（快照/历史数据连续）。
未识别的新子表：标签原样透传 + 日志告警（沿用「未映射标签透传」铁律），下次盘点再补枚举。

### D3 列映射：表头驱动（一处实现覆盖 9 子表）

复用 `_detect_fayifaer_columns` 的思路重写精简版：扫前 5 行找含「危险品名称」的表头行，
按列名关键词建映射（危险品名称/存放部位/规格/管理类别/当前数量/一昼夜使用量/库存上限/危险性），
未知列忽略（替考的孤例备注列自然吞掉）。危废库缺「一昼夜使用量」无需特判。

| 子表列 | InventoryView 字段 | 说明 |
|---|---|---|
| 存放部位 | storage_location | strip 换行/首尾空格 |
| 危险品名称 | material_name | 非空才成行（空行/标题行自然跳过） |
| 规格 | package_spec | **不解析**，透传字符串（85% 与 0.5kg/瓶 并存，仅展示用） |
| 管理类别 | category | 车间储罐/生产车间地面/危废库地面 |
| 当前数量/kg | quantity（unit=kg）→ total_quantity_t=/1000 | 空则 None |
| 一昼夜使用量/kg | **新字段 daily_usage_kg** | 见 D5 |
| 库存上限/kg | max_limit（÷1000）→ max_limit_unit=T | 与 R01-R03 同口径（现链路 `_limit_to_tonnes` 一致）；空则 None |
| 危险性 | hazard_classes | 复用 `_hazard_classes`（「易燃易爆」→仅 flammable 等既有规则） |

行标识：`id/feishu_record_id = "{sheet_id}:{行号}"`（如 `2RRpSr:3`，稳定且可追溯回单元格）；
`updated_at` 取 spreadsheet revision 无行级时间，落**读取时刻**（新鲜度信号语义降级为
「读取时间」，daily_report 判「今日是否更新」改按 revision 变化，见 D6）。

### D4 数量与单位的脏数据兜底

- 数值列 `_num` 语义照搬（逗号/占位符容错）；非数值 → None，不猜
- 空 sheet 跳过（`workbook-info` 先枚举 sheet_id+维度，行数 0 或首行无表头即跳）
- 全角％/不定/3300% 等仅存在于规格列 → 透传，不阻塞

### D5 一昼夜使用量：视图新字段（additive，不迁库）

`InventoryView` 加 `daily_usage_kg: Decimal | None`（默认 None，旧 reader 不动）；
`ChemicalInventoryRecordResponse` 加同名字段（可选，前端可显示「日用量」列）；
不入 ORM、不入 Bitable；快照 records 序列化自然带上（历史可回溯）。
日报分析暂不消费（保持口径不变），后续可做「日用量×安全周期 vs 库存」类规则（不在本期）。

### D6 日报编排与「今日是否更新」判定

- 19:30 分支：sheet 模式 → `reader.fetch_all(strict=True)` → `scan_inventory_views`（内存，不回写）→ `compute_daily_analysis` → `take_snapshot(records=views)` → 速递格子（含危险品日报群追加投递，均复用）
- `no_files_today` 语义变为 `read_failed`/空表告警；「未收到日报 Excel」文案改为「表格读取异常/无数据」
- daily_report 判「今日是否真更新过」原靠 Bitable ModifiedTime；sheet 模式改为**记录当日 revision**（读 metainfo 一次），revision 不变 → 日报标注「数据自 xx 未更新」（防止车间没填表被误读为平稳）

### D7 手工补录与速递文案

- 直读模式拒绝补录的文案 `RECEIPT_DIRECT_DISABLED_MESSAGE` 改为「请在飞书《危险品日报表》对应子表更新库存」
- 前端危化品页（`chemicalInventoryConstants.tsx`）：部门筛选项补 9 个新枚举；补录入口在 sheet 模式下隐藏（现有 direct 分支已拒绝，UI 同步）

### D8 环比断点（切换首日）

快照按 部门+物料 环比；切换当天旧部门枚举行全体消失、新枚举行全体新增 → surge/decline
全量误报。处理：切换首日（检测到 prev_snapshot 与当日源标记不一致）跳过环比段，日报
明示「数据源口径切换，本日不做环比」；次日恢复。快照表加 `source` 标记位（`bitable`/`sheet`）便于判定。

## 4. 分期与分票

**两期切分原则：一期只动读侧（换源直读上线，旧链路原样保留兜底，可一键回滚）；
二期在一期双跑对账验收通过、拍板退役后，才做旧链路删码与归档。两期各自独立可交付、独立可 revert。**

### 一期：换源直读上线（读侧切换 + 双跑对账窗口）

上线后状态：19:30 日报与所有读路径走《危险品日报表》直读；旧 Excel→Bitable 链路代码原样保留但
不再被调度执行（开关隔离），作为回滚路径。

| 票 | 内容 | 量级 |
|---|---|---|
| P1-T1 | `chemical_inventory_direct/sheet_reader.py`：metainfo 枚举 + 表头映射 + 视图构建 + 单测（fixture 用 2026-10-15 实读 9 子表 JSON，覆盖危废库缺列/空表/换行单元格/空数量） | ~300 行 |
| P1-T2 | 源开关 + gates + `open_reader()` 分支 + `bitable_config` connection + 快照 source 标记 | ~80 行 |
| P1-T3 | daily_job sheet 分支（跳过 Excel 拉取/Bitable 写入）+ revision 记录与「数据未更新」标注 + 行数骤降告警 + 文案（日报/速递/补录拒绝）+ D8 环比断点 | ~120 行 |
| P1-T4 | 前端：新部门枚举筛选项/标签、日用量列（可选）、补录入口隐藏 | ~60 行 |
| P1-T5 | **双跑对账脚本**（一期验收工具）：同日跑两源（sheet 视图 vs 旧链路 Bitable 总表当日数据）出 diff 报告（行数/物料集合/总量差），供每日人工核对 | 脚本 |

**一期出口条件（DoD）**：
1. 单测：9 子表真实 fixture 全字段断言 + 危废库缺列/空表/脏文本用例
2. 双跑对账连续 3–5 个工作日 diff 可解释（部门口径差异属预期，逐条归类）
3. 19:30 日报/速递正常出卡；revision 未变时正确标注「数据未更新」
4. `/api/safety/chemical-inventory/records|stats` sheet 模式正常返回（meta.mode=direct）
5. 回滚演练：开关拨回 bitable，行为与改造前一致

### 二期：旧链路退役（删码 + 归档，需一期验收 + 拍板后启动）

| 票 | 内容 | 说明 |
|---|---|---|
| P2-T1 | 删码批次（独立可 revert，参照 regulation-ingest 10/10 先例）：`excel_parser.py`、`daily_update.py`、`import_excel.py`、`chemical_inventory_daily_handler.py`（realtime）、daily_job 的群文件拉取分支 | 净删 ~1500 行 |
| P2-T2 | Bitable 总表（QoUXbLVcQaYAO7sod1CcUH3JnVd）转归档：停写冻结、连接标记 archived、历史只读保留 | 配置 + 文档 |
| P2-T3 | 文档与口径收尾：chemical-inventory-design 系列文档补「sheet 源」口径；速递/补录文案终版 | 文档 |
| P2-T4（可选增强） | 一昼夜使用量消费（日用量×安全周期 vs 库存规则）、跨源周报对比口径 | 拍板后另立设计 |

二期前置条件：一期 DoD 全绿 + 用户拍板「Excel 链路不再需要」（含确认各车间不再向危险品日报群
发 Excel、或发了也不再需要入库）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 车间改列名/加列 | 表头关键词映射 + 未识别表头 strict 模式告警（日报标注列异常） |
| 子表增删（发酵启用等） | metainfo 动态枚举 + 未映射子表透传告警，无需发版 |
| 飞书限流 | 每次全量 = 1 metainfo + ≤13 次 range 读，远低于限额；复用 300s TTL 缓存 |
| 源表被误清空 | strict 校验：行数较昨日骤降 >50% 时日报红标告警，不静默接受 |
| 切换日环比误报 | D8 首日跳过环比 |
| 历史快照不可比 | 快照 source 标记；跨源对比页面（如周报）后续再议 |

## 6. 验收标准

一期验收 = §4 一期 DoD（单测/双跑对账/日报速递/API/回滚演练五项）。
二期验收 = 删码批次全量跑绿既有测试基线 + 归档后历史快照可读 + 速递/日报文案终版生效；
若 P2-T4 增强启动，另立验收。
