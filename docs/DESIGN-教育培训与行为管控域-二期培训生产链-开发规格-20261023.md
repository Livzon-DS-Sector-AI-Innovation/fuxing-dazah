## 2. 硬约束

1. **分支**：`feature/warehouse-module` 唯一分支，直提不 push（push 由用户指示）；工作区常有兄弟批次脏文件——**commit 只 add 自己的文件清单**；
2. **模块边界**：safety 模块**不得 import** `app.modules.hr`（全仓零先例）。出题引擎=**契约复用、safety 侧独立实现**（JSON 键结构对齐 HR `EXAM_QUESTION_KEYS`，代码自持）；
3. **AI 出草案、人终判**：所有 AI 产物是草案/建议，终值由人确认或人工覆盖留痕；
4. **测试落点**：`backend/tests/modules/safety/test_*.py`（包内不放测试，包内测试坑）；pytest 基线有 4 个已知 live 数据污染红（`test_regulation_ingest` ×3、`test_ragplus_ingest` ×1），非新代码问题；
5. **黄色操作**（需用户确认后执行）：alembic 迁移、真实建表/写飞书。dry-run 先行是一期惯例；
6. `.scratch/` 不入库（gitignore）；设计文档进 `docs/`。

## 4. 链1：年度培训需求生成

### 4.1 数据流

```
五源取数 → 汇报文本(digest) → AI(training_demand_generation) → PG 草案表
        → 安环科评审(API 查询) → 逐行采纳(POST) → Bitable 培训表建计划行(状态=未开始)
```

**草案不直接写 Bitable 培训表**：D3-05 完成率=非取消行中已完成/应完成，草案直接入表会污染分母。草案存 PG 新表，采纳时才写 Bitable。

### 4.2 五源取数（全部走既有直读，无新连接）

| 源 | 读法 | 截断口径 |
|---|---|---|
| 危险源辨识 | opener(`hazard_id`,`ledger`)：岗位/不规范作业行为表现/现有管理控制措施 | 每岗位前 5 条行为，总 ≤200 行 |
| 隐患统计 | opener(`hazard`,`hazard`)：隐患类别（AI）计数 | TOP15 类别 |
| 违章统计 | opener(`training_behavior`,`violation`)：违章类别×等级计数 | TOP15 |
| 新法规 | PG `regulation_ingest` 相关表（completed 且本年度） | ≤30 条标题 |
| 上年完成 | opener(`training_behavior`,`training`)：上年行计算完成率+考核薄弱（合格率<100% 的主题） | 摘要 |

### 4.3 PG 草案表（alembic 迁移，黄色操作）

`training_demand_drafts`：id / year / position / topic / suggested_hours / form / audience / basis / is_statutory_gap / status(草案/已采纳/已驳回) / adopted_record_id / created_at / updated_at。幂等：同 year 重新生成=全量替换 status=草案 的行（已采纳/已驳回保留）。

### 4.4 采纳写入映射

position→`组织部门`（多选，拆分）、topic→`培训名称`、suggested_hours→`培训学时`、form→`培训形式`、状态→`未开始`、备注→`依据：{basis}；对象：{audience}`（is_statutory_gap 再加 `【法定缺口】`前缀；表无对象列，audience 落备注供排课人参考）。

### 4.5 API

- `POST /api/safety/training-behavior/demand/generate` {year} → 触发生成（异步任务模式对齐既有 AI 端点先例，同步返回亦可——轮询/同步由实现票定，倾向同步+超时 120s）
- `GET  /api/safety/training-behavior/demand/drafts?year=&status=` → 清单
- `POST /api/safety/training-behavior/demand/drafts/{id}/adopt` → 写 Bitable+置已采纳
- `POST /api/safety/training-behavior/demand/drafts/{id}/reject`

### 4.6 提示词（定稿，temp 0.2，expected_keys=[summary, demands, statutory_notes]）

**SYSTEM_PROMPT**：

```
你是工厂安全培训计划编制专员。基于给定的五类输入数据，生成下年度培训需求清单草案，供安环科评审。

要求：
1. 每条需求必须给出可溯源的依据（basis）：引用输入中出现过的具体不规范作业行为、隐患类别及其次数、违章类别及其次数、或法规标题；禁止编造编号、次数或法规名；
2. 对照法定底线标注缺口（is_statutory_gap=true）：危险物品单位新员工岗前三级教育≥72学时、从业人员年度再培训≥20学时、主要负责人与安管人员年度再培训≥16学时（3号令§9/§13加严口径）；输入显示未安排或学时不足的，必须单列缺口行；
3. 相同岗位相同主题合并为一条；常规需求建议学时取 2/4/8 的整档，法定缺口行按法定学时填（如 72/20/16）不受整档限制；建议形式从线下/线上/实操中选；
4. 全部需求不超过 40 条，按「法定缺口 > 高风险岗位 > 高发隐患/违章 > 新法规宣贯」排序；
5. 只输出 JSON，不输出其他内容。

输出格式：{"summary": "<一句话总评>", "demands": [{"position": "<岗位>", "topic": "<培训主题>", "suggested_hours": 4, "form": "线下", "audience": "<对象说明>", "basis": "<依据>", "is_statutory_gap": false}], "statutory_notes": ["<法定缺口补充说明>"]}
```

**build_user_prompt 模板**：

```
## 一、危险源辨识摘要（岗位 × 不规范作业行为 × 控制措施）
{hazard_id_digest}

## 二、本年度隐患统计（类别 × 次数）
{hazard_stats}

## 三、本年度违章档案统计（类别 × 等级 × 次数）
{violation_stats}

## 四、本年度新收录/修订法规清单
{regulation_list}

## 五、上学年培训完成情况
{last_year_summary}

请生成下年度培训需求清单草案。
```

## 5. 链2：讲义与试卷生成

### 5.1 数据流

```
POST generate-material {training_record_id, material_type: lecture|exam|both, config?}
→ 读 training 行（主题/类别/学时/对象）
→ knowledge_md 文档选择器（§5.2）
→ AI 生成（讲义 JSON / 试卷 JSON）
→ docx 渲染（safety 侧独立渲染器）
→ upload_media+附件注册 挂「课件与试卷」列
→ 行备注追加生成记录（幂等标记，防重复生成同类型）
```

### 5.2 knowledge_md 供给（现实口径：无进程内 RAG）

复用 `knowledge/query_service.py` 的 `_build_document_context`（调用先例见 `contractor_admission/service.py` ④——注意函数本体不在该文件）：从知识域（`knowledge` 直读/PG knowledge 表）按主题关键词+标题匹配筛文档，取正文片段拼 markdown，片段格式=该函数既有格式（`[N] 文档标题` 编号+条款与正文片段，`---` 分隔），总量 ≤8000 字。匹配不到→空串（提示词已兜底「待补法规出处」）。RAG HTTP 检索列为后续增强，不在本期。

### 5.3 docx 渲染与上传（先例路径）

- 渲染：对齐 `drill_eval_generation` 的 docx 生成器模式（python-docx；试卷渲染=单选/判断/多选/填空四节+答案页，样式参照 HR `ai_exam_service` 的排版但代码独立）；
- 上传：`SafetyBitableClient.upload_media`（`parent_type=bitable_file`）拿媒体 token → `_build_attachment_extra` 附件注册写「课件与试卷」列——**这是与照片回填同构的既有链，实现票第一件事=跑通此链的最小验证**。备选降级：`upload_drive_file` 得 Drive token 后把下载链接写`备注`（附件列不吃链接，仅兜底）。

### 5.4 提示词——讲义（temp 0.2，expected_keys=[title, objectives, sections, key_takeaways, references]）

**SYSTEM_PROMPT**：

```
你是工厂安全培训讲师。根据培训基本信息与检索到的法规/规程/MSDS 片段，生成讲义要点卡（授课大纲级，非逐字稿）。

要求：
1. 章节要点必须来自给定片段或普适安全常识；引用条款、限值、数字时必须与片段一致，并标注来源名（如「GB 30871-2022 §5.2」须在片段中真实出现）；
2. 检索片段为空时，按主题通用要求编制，并在 references 中注明「待补法规出处，讲师定稿前补核」；
3. 要点密度与学时匹配：每学时 3-5 个要点；每个要点是可直接讲授的行为或规则表述；
4. key_takeaways 不超过 8 条，是学员必须带走的内容；
5. 只输出 JSON。

输出格式：{"title": "<讲义标题>", "objectives": ["<培训目标>"], "sections": [{"heading": "<章节名>", "points": ["<要点>"]}], "key_takeaways": ["<核心要点>"], "references": ["<来源名>"]}
```

**build_user_prompt 模板**：

```
## 培训信息
- 主题：{topic}　类别：{category}　学时：{hours}　对象岗位：{position}

## 检索片段（来源见 [N] 编号标注）
{knowledge_md}

请生成讲义要点卡。
```

### 5.5 提示词——试卷（temp 0.1，expected_keys=按 config 请求的题型键）

config 键名对齐 HR（`choice_count`/`true_false_count`/`multi_choice_count`/`fill_count`，默认 5/5/0/0）。**expected_keys 只列数量>0 的题型键**——`chat_parsed` 对缺失键直接抛错（`platform/integrations/ai/client.py`），把缺省题型列进 expected_keys 会让默认路径必失败。

**SYSTEM_PROMPT**：

```
你是工厂安全培训考核出题人。根据给定材料（讲义要点 + 检索片段）生成试卷，严格基于材料内容命题，禁止编造材料中不存在的知识点；每道题标注 source（材料中的来源名或「讲义要点」）。
各题型题量必须严格按指定数量出足，不得少出或多出。
干扰选项要合理、有区分度，正确答案在各选项间均匀分布，不要固定为 A；多选题有 2-3 个正确答案，answer 用逗号连接（如 "A,B"）；判断题 answer 只能是"正确"或"错误"，正确与错误大致各半；填空题 question 中用______表示空位且不能出现答案。
只输出 JSON，不输出其他内容。
```

**build_user_prompt 拼装**（对齐 HR `ai_exam_service._build_prompt` 模式：题型要求与输出格式骨架均按 config 动态拼、仅含数量>0 的题型，代码内 f-string 拼装、不做静态 str.format 模板）：

```
请根据以下材料生成试卷：{question_reqs}。

输出格式：{ {format_skeleton} }

材料：
{material}
```

- question_reqs 逐题型句式（分号连接，数量>0 才出现）：
  - 单选「出 {n} 道单选题（4 选项 A/B/C/D，只有一个正确答案）」
  - 判断「出 {n} 道判断题（answer 只能是"正确"或"错误"，正确与错误大致各半）」
  - 多选「出 {n} 道多选题（4 选项，有 2-3 个正确答案）」
  - 填空「出 {n} 道填空题（将关键知识点挖空，question 中用______表示空位，question 里不能出现答案）」
- format_skeleton 逐题型片段（逗号连接，数量>0 才出现）：
  - `"choice_questions": [{"question":"...","options":[{"label":"A","text":"..."},...],"answer":"A","source":"..."}]`
  - `"true_false_questions": [{"question":"...","answer":"正确","source":"..."}]`
  - `"multi_choice_questions": [{"question":"...","options":[{"label":"A","text":"..."},...],"answer":"A,B","source":"..."}]`
  - `"fill_blank_questions": [{"question":"...","answer":"关键词","source":"..."}]`

校验对齐 HR `_validate_exam` 语义（选项结构/answer 合法性/数量、超出截断），safety 侧独立实现。

## 6. 链3：签到/成绩单解析（vision）

### 6.1 数据流

```
POST parse-record {training_record_id}（取该行「签到表」附件列首个文件）
→ vision 模型解析（temp 0.1）
→ 回填 实到人数 / 考核合格人数（文本数字列）+ 备注追加解析明细

```

vision 调用先例：体检报告解析（场景 `oh_exam_report_parsing`，`create_ai_service("vision")`），实现票先读该服务照抄调用形态。

### 6.2 提示词（temp 0.1，expected_keys=[doc_type, attendance_count, names, passed_count, scores, confidence, unrecognized, notes]）

**SYSTEM_PROMPT**：

```
你是培训留痕单据解析员。识别图片是签到表还是考核成绩单，并转录内容。

要求：
1. 名单按单据原样逐名转录，不得参照应到名单补名、删名或对名；字迹无法辨认的名字放进 unrecognized，禁止猜测补名；
2. 分数只抄录不推算；attendance_count 只数单据上实际签到/出场的人，成绩单无出勤信息时置 null；合格人数仅当单据上有明确及格线或"合格"勾选时统计，否则 passed_count 置 null；
3. 手写体模糊、照片残缺、打印倾斜等影响识别的情况，confidence 降为 medium 或 low，并在 notes 说明；
4. 与培训签到/考核无关的图片，doc_type 判"无法识别"，其余字段置 null（names/scores/unrecognized 为空数组）；
5. 只输出 JSON。

输出格式：{"doc_type": "签到表|成绩单|无法识别", "attendance_count": 18, "names": ["<姓名>"], "passed_count": 16, "scores": [{"name": "<姓名>", "score": "92"}], "confidence": "high|medium|low", "unrecognized": ["<辨认不清的姓名>"], "notes": "<识别情况说明>"}
```

**build_user_prompt 模板**：

```
## 培训上下文
- 培训名称：{training_name}　应到人数：{expected_count}　考核方式：{assessment}

请解析这张单据图片并按约定 JSON 输出。
```

### 6.3 回填口径

confidence=high → 直接回填数字列；medium/low → 数字列不回填，明细进备注（`AI解析(confidence=medium)：…`）待人工。doc_type=无法识别 → 仅备注记录。

## 11. 已知坑（一期踩过，直接绕）

1. 建表/写飞书慢响应会误报失败但实际成功——幂等按名复用吸收，勿信任单次失败结论；
2. `bd_fields.to_millis` 吃原始值（int/str）不吃 datetime；日期读出统一 `datetime_ms`→`+8h` 转北京日；
3. 引擎任务协程禁止内联跑整轮 AI（派发器模式，见 scheduled.py `_dispatch_round`）——二期全手动 API 无此问题，但若加定时触发必须走派发器；
4. alembic 迁移播种要 ON CONFLICT DO NOTHING（先例 48d67b2a）；
5. Bitable 单选列写未注册选项会自动扩选项——写枚举值务必用蓝本既有值，防脏选项；
6. 工作区脏文件多属兄弟批次，`git add` 只点名自己的文件；commit message 风格 `feat(safety): S6二期…`。
