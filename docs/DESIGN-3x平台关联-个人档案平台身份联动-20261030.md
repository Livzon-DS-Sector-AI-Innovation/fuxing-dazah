# DESIGN — 3.x 平台关联：个人档案平台身份联动（F3 身份卡 · F4 应持证核验 · F5 对账提醒）

> 2026-10-30。上游：OH 个人完整档案一期已交付（cf40d988，五源聚合档案页）；平台人员 API 当日实弹探测。
> 关联文档：`DESIGN-3x平台关联-承包商实名台账全员主档与风险分区底图-20261026.md`（F1/F2）。

## 0. 一句话

把 3.x 平台「活的人员主数据」（岗位/直属上级/在职状态/工号）以只读方式挂进 dazah 个人档案页，先补一张「平台身份卡」，再沿「岗位→应持证」和「在职状态→离岗体检」两条合规推理链扩展。

## 1. 数据源实测（2026-10-30 实弹，非文档推断）

### 1.1 接口（Apifox「企业组织档案」域，Client token 可用）

| 接口 | 路径 | 用途 | 实测 |
|---|---|---|---|
| 账号查询 | `GET /api/tiji-system/openapi/account/query` | 按姓名/手机/**工号**/证件号/登录账号精确查（仅在职） | 工号查 1 条命中；姓名查 1 条命中；**身份证查 0 命中** |
| 人员详情 | `GET /api/tiji-system/openapi/user/detail` | 按平台人员 id 查详情 | 张国东(id=8212) 命中，字段见 1.2 |
| 全员主档 | `GET /api/tiji-system/user/page` | 1400 人分页 | F1 已接（org_directory 岗位字典在用） |

### 1.2 user/detail 字段实况（抽样 5 人：张国东/杨文康/闫亚超/张雨潇/陈凛超）

| 字段 | 填充 | 对 dazah 的价值 |
|---|---|---|
| `postName` 岗位 | **全实**（电焊工/庆大磺黏粗提操作工/1#冻干线冻干出料操作工…） | OH 台账岗位大面积空（张国东 OH「-」平台「电焊工」）——**最大增量** |
| `deptName`/`deptWholeName` | 全实（含全路径） | 部门漂移对账（§5.3 实证差异） |
| `directLeaderId/Name` 直属上级 | 全实 | OH「部门安全员」空时的兜底展示 |
| `jobNo` 工号 | 全实 | OH employee_no 43% 缺失的补齐来源 |
| `telephone`/`email` | 多数实 | 展示增量 |
| `status` 在职(1/0) | 实 | 离岗体检提醒钩子（§5.2） |
| `idCardNo` | **恒空** | 身份证键不可用（结论 §1.3） |
| `entryDate`/`education`/`gender`/`nation`/`healthStatus`/`imageBase64` | 全空（0/5） | schema 支持但未填，接口留着，展示层容空 |

### 1.3 数据活跃度与关联键结论

- 抽样 `updateTime` 全部落在近一周（多条当天）→ **平台主档在持续维护**（疑 HR 侧同步），值得依赖。
- **关联键定案：工号（OH `employee_no` ↔ 平台 `jobNo`）＞ 姓名+部门收窄。身份证键不可用。**
- 实证数据冲突一枚：杨文康 OH 台账部门=精制工程一部，平台=提炼工程二部——两边有一旧（§5.3 对账）。

## 2. 分期与红线

| 期 | 内容 | 工作量 |
|---|---|---|
| **F3 一期** | 档案页「平台身份卡」+ 工号/岗位差异展示 | ~1 天 |
| **F4 二期** | 岗位→应持证核验（映射表 + AI 建议确认流 + 档案区块） | 2–2.5 天 |
| **F5 三期** | 应检对账 / 离岗体检提醒 / 部门漂移对账 | 1–1.5 天 |

**不做（查实无意义/违反口径）**：平台培训联动（教育培训域零对外 API、内部仅 2 例三级培训 LCP 试过即弃——培训联动仍以 dazah 自有签到表解析链为准）；定位/轨迹（在线全 0）；人员 CRUD 写接口（只读口径）；承包商门禁联动并入档案（F1 扩展另议，见 P6）。

## 3. F3 平台身份卡（一期详细设计）

### 3.1 匹配链（oh_person → 平台人员）

```
OH person（直读行/镜像行均可）
  ├─ employee_no 非空 → account/query(jobNo=employee_no)     ← 主路径，精确
  ├─ miss → account/query(nickname=name) → 命中多条时按 deptName==person.department 收窄
  │         仍多条/零条 → unmatched（不猜测，见 P3）
  └─ 命中 → 取平台 id → user/detail(id) → 身份卡字段
```

- 匹配失败的档案页显示「平台未匹配」占位（EmptyGuide），不报错。
- 平台返回与 OH 同字段冲突（部门/岗位）时**并排展示 + 差异标记**，不做任何回写（P1）。

### 3.2 服务与缓存

- 新 `service/platform_identity.py`：`PlatformIdentityService`，注入式 client（测试替身），纯函数 `match_platform_user(person_fields, account_rows)` 可单测。
- 缓存：进程内单键（平台人员 id）TTL 缓存，默认 **600s**（`SAFETY_PLATFORM_IDENTITY_CACHE_TTL_SECONDS`，对齐 contractor_workers 人员缓存窗口）；1400 主档全集不为此重拉。
- 三态：`live`（含 fetched_at）/ `degraded`（缓存时点）/ `empty`（平台不可用且无缓存），沿用 org_directory 信封口径。
- 隐私：个人明细**不落库**，仅进程内存 TTL；身份证等敏感字段不出现（平台也空）。

### 3.3 API 与前端

- **不新建端点**：扩展现有 `GET /oh/persons/{id}/profile` 响应，新增 `platform` 节：
  ```json
  "platform": {
    "status": "live | degraded | empty | unmatched",
    "fetched_at": "...",
    "match_basis": "job_no | name_dept",
    "person": {"platform_id": "8212", "post_name": "电焊工", "dept_name": "...",
                "dept_whole_name": "...", "direct_leader": "汪功剑", "job_no": "111000561",
                "telephone": "...", "email": "...", "status": "在职", "entry_date": null}
  }
  ```
- 档案页在「基本信息」卡下方加 SectionCard「**平台身份（3.x）**」：左 OH 值右平台值并排；差异（岗位/部门）高亮「两侧不一致」标签；卡头标注数据时点。
- OH 缺工号而平台有时：展示「平台工号 xxx（台账未登记）」——只展示，回写 Bitable 待 P1。

## 4. F4 岗位应持证核验（二期）

### 4.1 数据链

```
user/page(1400) postName ──(映射表 post_cert_map)──▶ 应持 cert_category+operation_type
                                                          │
cert_direct 持证台账（special_op kind，按姓名+部门反查）◀───┘
                                                          ▼
                              档案页「应持证」区：应持 vs 实持 vs 复审到期
```

### 4.2 映射表 `safety.post_cert_map`

| 列 | 说明 |
|---|---|
| post_name | 平台岗位名（或岗位族，二选一见 P4） |
| required_cert_category | 应持证件类别（特种作业操作证等） |
| required_operation_type | 作业项目（熔化焊接与热切割/低压电工作业…，对齐持证台账 `operation_type` 词汇） |
| source | seed / ai_confirmed / manual |

- 初版 **seed 硬规则**：电焊工→熔化焊接与热切割、电工→低压电工等常识映射（预计 <20 条）；其余岗位走 **AI 建议→人工确认**（完整复用 #2/#4 已交付的「AI 资产确认」组件与 suggestion 中间表模式，场景=postName 全集→建议应持证→确认页→落表 source=ai_confirmed）。
- 消费方：档案页应持证区（本设计）+ 持证预警页/S14 副台账的「该岗位应持而未见证」清单（同一映射两处消费）。

### 4.3 档案页呈现

身份卡内嵌「岗位应持证」子区：每行 `应持：熔化焊接与热切割作业证 · 实持：✓/✗ · 复审：2027-05-01`。未匹配映射的岗位显示「岗位未配置应持证规则」。

## 5. F5 对账与提醒（三期）

### 5.1 应检对账（设计文档 F1 §1.3 预留钩子落地）
- 1400 在职主档 vs OH 997 人员台账 → **在厂无 OH 档案名单**（约 400 差额的定性：非接害 or 漏管）。
- 出口：`GET /safety/oh/reconciliation`（名单+分类计数）+ OH 域页一个入口按钮；批任务日级（搭 org_posts 日级缓存的便车）。

### 5.2 离岗体检提醒（合规硬指标）
- 平台 `status=0`（离职）且 OH 无 `post_employment` 体检记录 → 「离职未见离岗体检」清单。
- 出口候选（P5）：安全速递格一格 / Agent 每日问询附带 / 仅报表。**只提示不自动建单**。

### 5.3 部门漂移对账
- 同名比对 OH 部门 vs 平台 deptName 不一致清单（杨文康实例已证存在），供台账治理。

## 7. 测试与验收

- **单测**：匹配链纯函数（工号命中/姓名+部门收窄/多命中放弃/零命中/平台字段容空）；三态降级（client 注入替身）；post_cert_map 确认流（复用 #2/#4 测试模式）。
- **集成锚定**：真实平台冒烟锚定两例——张国东（工号 111000561→id 8212→电焊工）、杨文康（部门冲突例）；断言响应结构不断言平台数据值（无 SLA）。
- **浏览器验收**：档案页身份卡渲染、差异标签、未匹配占位、平台不可用降级文案。
- 回归：OH 域全量（cf40d988 基线 1159 过 + 12 预存环境红）。

## 8. 风险与边界

- 平台接口无 SLA → 全链路三态降级，档案页主区块不受身份卡失败影响（身份卡是第 6 源，独立降级）。
- 同名误配防线：工号精确优先 + 部门收窄 + 多命中放弃（P3），展示层始终标注 `match_basis`。
- 隐私红线：个人明细不落库、不打日志（仅计数日志）；F1「个人明细不落库」口径延续。
- 只读红线：平台人员 CRUD/门禁写接口一概不碰。
- 平台字段大面积空（入职/学历/照片）→ 展示层容空设计，不因空报错。
