# DESIGN — 安全目标责任与绩效（S1 goals）：体系标准符合性核查引擎（2026-10-21）

## 0. 一句话

S1 的定位从「三张静态台账」改为**「标准 × 运行数据 = 符合性判定」的核查引擎**：把安全目标、责任、绩效整理成一份**可核查的标准清单**（每条=一个可衡量的体系要求，如「年度至少开展 1 次综合应急演练」），每条标准绑定系统内一个**指标取数器**，平台自动从各域运行数据算出完成值并判定**达标 / 进行中 / 未达标 / 无数据**——目标=标准清单，责任=每条标准挂责任部门/责任人，绩效=标准达成汇总。四态判定 + 证据下钻 + 周期定格留痕是本域的业务动作，与总驾驶舱（运营数据监控）视角互补不重复。

> 2026-10-21 拍板背景：首版方案（履职绩效矩阵/速递格/提醒链/三台账展示）被否——展示类与驾驶舱重复、纸档业务（责任书）不线上化。本方案是用户给定的第二方向：**标准作为评价体系运行的尺度，从运行数据对比标准**。

**直接复用**：三态信封口径（not_connected/live/degraded）；analyze 单点计算防口径漂移；直读 Reader 与 `BitableConfigError` 判源（无数据态的判定依据）；身份解析与部门归口（`responsible_mapping`）；调度底盘 no_source 铁律；Agent 只读工具注册模式（business_agent read_tools）。

## 2. 总体架构

```
标准清单（Bitable「体系标准核查表」，安环科维护，按年版本化）
  每条：标准条款 · 依据 · 要素归属 · 指标键 · 比较符 · 目标值 · 周期 · 责任部门/责任人
        │ 指标键为空 = 人工核查项（读「人工核查结果」列）
        ▼
指标注册表（代码，metric_key → 取数器）
  drill.count(综合/专项) · hazard.on_time_rate · oh.exam_rate · workticket.audit_rate
  facility.on_time_rate · contractor.admit_rate · visitor.insurance_rate · …
        │ 取数器统一返回 MetricValue(value) | NoData(源未接入)
        ▼
判定引擎（纯函数：标准 × 值 × 今日 → 四态）
  达标 / 进行中(周期未满) / 未达标(周期已满) / 无数据
        ├── 实时视图：goals 页核查清单（八要素分组+证据下钻）
        ├── 周期定格：季末/年末 snapshot 落 DB（绩效评定留档）
        ├── 季度/年度汇总：速递格一条（可选，拍板 P3）
        └── Agent 工具：query_standard_compliance（「今年综合演练做了吗」可答）
```

三层各自独立：清单是业务事实源（人维护）；注册表是代码能力（加指标=加取数器）；引擎是口径单点。**完成值与达成状态一律平台实时计算，不回写 Bitable**（全局铁律）。

## 3. 数据模型

### 3.1 Bitable「体系标准核查表」（goal_indicator 蓝本的实质化升级，registry kind 沿用或改名 `standard_check`）

| 列 | 类型 | 说明 |
|---|---|---|
| 标准编号 | text | S1-001（人编，稳定锚点） |
| 年度 | single_select | 2026（清单按年版本化，年初复制上年修订） |
| 标准条款 | text | 「年度至少开展 1 次综合应急演练」 |
| 依据 | text | GB/T 33000-2016 §5.6.3 / 应急预案管理办法§33 / 公司年度安全目标文件 |
| 要素归属 | single_select | 八要素：目标职责/制度化管理/教育培训/现场管理/风险管控与隐患治理/应急管理/事故管理/持续改进 |
| 指标键 | single_select（枚举=注册表 keys，播种时生成） | 空=人工核查项 |
| 比较符 | single_select | ≥ / ≤ / = |
| 目标值 | text | 1 / 95 / 0 |
| 单位 | single_select | 次 / % / 人 / 天 |
| 周期 | single_select | 年度 / 半年 / 季度 / 月度 / 长周期(3年) |
| 责任部门 | multi_select | |
| 责任人 | person | |
| 上次完成日期 | datetime | **长周期项判定锚点**（如"安全评价每3年≥1次"：今日−上次完成 ≤3年 即达标）；周期项不用 |
| 人工核查结果 | single_select | 已完成 / 未完成 / 不适用（仅指标键为空的行生效） |
| 备注 | text | |

registry：goals 域 kinds 调整——`goal_indicator→standard_check`（核查清单，主表）；`responsibility/investment` 两 kind 从蓝本移除（责任书纸档不做台账；投入台账无核查语义，若将来要登记再单议）。播种=标准清单初版（附录 A）。

### 3.2 指标注册表（代码，`service/standard_check/metrics.py`）

```python
@dataclass(frozen=True)
class MetricSpec:
    key: str            # "drill.count.comprehensive_or_special"
    label: str          # "年度综合/专项演练次数"
    unit: str           # "次" | "%" | ...
    source_domain: str  # "emergency_drill"（健康度墙同源命名）
    periods: tuple[str, ...]           # 支持的周期窗口
    settle: str         # "early"(计数下限型,满足即达标) | "period_end"(比率/上限型,周期满才定)

MetricResult = MetricValue(value, evidence) | NoData(reason)
# evidence: 证明明细（演练 record 链接/隐患筛选条件），前端下钻用
```

取数器签名 `async def compute(period: Period) -> MetricResult`；BitableConfigError/源未接入 → `NoData`（**无数据 ≠ 未达标**：系统没接这块不等于没做，冤案零容忍）。

### 3.3 DB 新表（alembic，schema=safety，1 张）

**`safety.standard_check_snapshots`**（周期定格留痕）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| standard_no / year | text / int | 定格对象（清单行冗余快照条款文本+目标值，防清单后续修订篡改历史） |
| period_key | text | 2026 / 2026-Q3 / 2026-09 |
| metric_key / actual_value / operator / target_value | | 判定输入原值 |
| status | text | achieved / missed / no_data / manual_done / manual_missed |
| evidence | jsonb | 证据引用快照 |
| frozen_at | timestamptz | |

约束：唯一 (standard_no, period_key)。年度绩效评定/标准化自评/迎检 = 直接导出年度 snapshot，不再现场重算。

### 3.4 判定引擎（纯函数，today 可注入）

```
无指标键        → 读人工核查结果列 → 已完成/未完成
长周期(3年)项    → 今日 − 上次完成日期 ≤3年 → 达标；>3年或空 → 未达标（周期常开，无"进行中"）
取数 = NoData   → 无数据（附原因：源未接入）
比较满足        → settle=early 达标；settle=period_end 且周期未满 → 进行中·当前达标
不满足·周期未满 → 进行中（附「距周期末 N 天」）
不满足·周期已满 → 未达标
```

**半自动项**（数据在系统但分母/口径需人工核定，如证书类）：一期按人工核查项勾结果，行上标注「系统有台账可辅助」，注册表二期再升级取数器。

周期窗口北京时间日界（与 EHS 变更/速递同口径）；上限型（事故=0）周期内永远「进行中·当前达标/当前超标」，年末定格。

## 4. 业务功能

### 4.1 标准核查清单（核心视图）

`GET /api/v1/safety/goals/standards?year=&element=&status=&department=` → `{status, summary{achieved,in_progress,missed,no_data,rate}, groups[{element, rows[{no,clause,basis,period,target,actual,status,residual_days,department,owner,evidence}]}]}`。数据流：直读核查表全量 → 逐行取数（注册表按 metric_key 分组去重，同 key 同周期只算一次）→ 引擎判定 → 聚合。清单表未建/未接入 → not_connected（页面引导建表，附蓝本与附录 A 初版）。

### 4.2 证据下钻

每行「做到了」要能看到凭据：`GET /api/v1/safety/goals/standards/{record_id}/evidence` → 取数器附带的明细（如 3 条演练记录的日期/名称/record_url 直达、隐患筛选器等价条件）。无数据行附原因与「该指标依赖 XX 域接入」的指引。

### 4.3 周期定格（调度 1 项）

每季度首日 08:20 定格上一季度全部季度/月度项 + 年度项快照落 DB；每年 1 月 1 日定格上年度（先于月度速递/年报类任务错峰）。清单行删除/标准废弃 → 不定格（snapshot 天然留档）。任务运行中心留痕，no_source 铁律。

### 4.4 季度符合性速递格（可选，拍板 P3）

季度定格完成后一条速递格 `standard_compliance`：「上季度标准达成 X/Y · 未达标：条款摘要（责任部门）· 无数据 Z 项」。不 @ 个人、不排名——达标情况的责任落点在页面清单里看得见，速递只做存在感通报。

### 4.5 Agent 只读工具

`query_standard_compliance(year?, element?, status?)` 注册进 read_tools（照既有直读工具手法）：「今年的综合应急演练做了吗」「哪些标准还没达标」Agent 直接可答，答案带证据引用。

### 4.6 年度绩效评定素材（不做报告生成器）

年度 snapshot 导出（页面年份切换 + CSV/打印）即绩效评定/自评的「目标责任绩效达成表」。不建 AI 报告链——首版被否，保持克制；将来真要写分析段，Agent 对话即可。

## 8. 风险与对策

- **指标口径争议**（按期整改率的分母、体检率的应检人数）：每个取数器 docstring 写死口径公式，页面「凭据」里展示同款文案；口径变更=改代码+快照天然保留旧口径历史
- **取数性能**：一页清单 ≤50 行、去重后指标 ≤15 个/次加载，各源直读 TTL 300s 复用，无压
- **清单维护断档**（年初没人复制新年度清单）：年初首个工作日检测无当年清单行 → 速递格提醒一次（复用 no_source 留痕模式，不建提醒链）
- **冤案风险**：无数据态永不计入未达标；evidence 必须可点验；人工项与自动项视觉区分（自动项带「系统核查」小标）
